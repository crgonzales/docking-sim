# Phase 2: Discrete RCS Thrusters, Sensors & EKF Implementation Plan

## Overview

Give the sim real physics and real flight software: a numeric RK4 truth propagator verified against the CW analytic oracle, a 16-jet Draco-like RCS model with min-impulse/quantization and propellant depletion, a torque-aware thruster allocator, seeded sensor models producing `SensorFrame`, an EKF translational navigator gated by NEES chi-square consistency, PID and LQR controllers behind the existing selector, and a `SimLoop` public API that replaces the Phase 1 stub emitter in one file. After this release the HUD numbers and the chaser's approach motion are produced by actual dynamics, estimation, and closed-loop control.

## Problem Statement

v0.2.0 fakes everything past the telemetry bus. Phases 3–5 (6-DOF, MPC, scenario mode) need the truth/FSW split, the injection seam, and the estimation stack to exist and be test-hardened first.

## Solution Architecture

All new physics/FSW lives in `packages/sim-core` (pure TS). One integration point in `apps/web`: `stubEmitter.ts` is replaced by `simEmitter.ts`, exercising the seam designed in Phase 1.

Data flow per ARCHI: `SimLoop` owns `TruthState` and steps truth at `TRUTH_HZ` (RK4). Every FSW tick (`FSW_HZ`) it samples sensors from truth (seeded noise), calls the pure `FswTick(SensorFrame) → {ThrusterCommand, TelemetryFrame, NavDiag}` (return extended this phase — see Type Definitions), applies the commanded on-times through the thruster model back into truth, and emits telemetry. External actors (UI now, ScenarioDirector later) touch the sim only through `SimLoop`'s public command + injection APIs — the honesty-invariant seam the Phase 5 spec tests (§7.4) will rely on.

**Attitude in Phase 2 (documented assumption):** perfect Hill-frame attitude hold, treated kinematically consistently: a body fixed to the LVLH frame rotates at orbital rate, so truth propagates `q_BI` at the constant LVLH angular velocity **ω = n·ẑ** (Hill axes; d x̂/dt = n ŷ for the circular target orbit), the gyro reads `[0, 0, n]` plus seeded noise, and the attitude sensor reports the corresponding `q_BI` plus small noise. No attitude dynamics or control exist this phase; Phase 3 replaces exactly this kinematic hold with 6-DOF + MEKF.

**NEES placement (honesty):** NEES needs truth, so FSW cannot compute it. `FswTick`'s return carries an FSW-owned diagnostic block (`nav_diag`: full 6-state estimate + full 6×6 covariance — the filter exposing its own belief, no truth involved). The `SimLoop` (truth-privileged) computes the **full-state 6-DOF NEES** `eᵀP⁻¹e` (e = truth − estimate over position and velocity, full covariance with CW cross-terms) and fills `TelemetryFrame.nees` after the FSW call. Consistency gate: per-epoch **ANEES across N ≥ 50 seeded runs** against the pointwise **[χ²₆ₙ(0.025)/N, χ²₆ₙ(0.975)/N]** band (chi-square with 6N degrees of freedom scaled by N — not the single-run 6-DOF interval), evaluated over the converged window (sim time 60–300 s). Pass criteria avoid the multiple-comparisons trap of demanding every epoch pass a 95% band: **(a) ≥ 90% of epochs in the window lie inside the pointwise band, and (b) the window-mean ANEES lies inside the band.** FSW itself never reads truth; tests enforce this.

## Implementation Details

### 1. Seeded RNG utility

**File**: `packages/sim-core/src/rng.ts` (new)

- mulberry32-class PRNG plus Box-Muller gaussian sampling.
- Named substreams derived from the master seed (`deriveSeed(master, 'sensors.range')` style) so subsystems draw independent, reproducible sequences and adding a consumer never perturbs existing streams.

### 2. Truth dynamics & propagator

**File**: `packages/sim-core/src/dynamics.ts` (new)

- CW relative translational dynamics as an ODE (mean motion `n` from `MU_EARTH_M3_S2` and orbit radius constant) plus external specific force from thrusters.
- Fixed-step RK4 at `TRUTH_HZ`; steps `TruthState.r_hill_m`, `v_hill_mps`, and `prop_kg` (depletion below). `q_BI` propagates kinematically at the constant LVLH rate ω = n·ẑ and `w_body_rps = [0, 0, n]` (see the attitude assumption above) — no attitude dynamics this phase.
- Oracle contract: free drift (zero thrust) must match `propagateCW` at small separations within tight tolerance over multi-orbit spans.

### 3. Thruster model (16-jet Draco-like)

**File**: `packages/sim-core/src/thrusters.ts` (new)

- Geometry table: 16 jets in 4 canted clusters at the vehicle corners; per-jet body position, unit thrust direction (canted so axes couple — the allocator has real work), thrust magnitude. Config defaults: 25 N per jet, min on-time 20 ms, on-time quantized to the truth tick, Isp 220 s.
- Vehicle mass model: dry mass + `prop_kg` (defaults chosen so wet mass ≈ 1000 kg with the scenario's 24.0 kg prop); depletion `ṁ = F/(Isp·g₀)` summed over firing jets; acceleration uses current total mass.
- Per-jet state honored by truth application: `nominal | isolated | stuck_open | stuck_closed` (the injection surface Phase 5's `THRUSTER_STUCK`/`ISOLATE_THRUSTER` map onto). Stuck-open fires regardless of command; isolated/stuck-closed never fire.

### 4. Thruster allocator (FSW-side)

**File**: `packages/sim-core/src/allocator.ts` (new)

- Maps a commanded force vector (body ≡ Hill this phase) to per-jet on-times for the next FSW tick via a **bounded non-negative least-squares (active-set NNLS) solve** over `0 ≤ onTime_i ≤ 1/FSW_HZ` for the available (non-isolated) jet set — objective: force-tracking error primary, net-torque magnitude as a weighted secondary term. Plain pseudo-inverse + clamping is explicitly not acceptable (clamping corrupts both achieved force and torque). After the solve: min-impulse deadband, then quantization to the truth tick; the allocator's return reports both the **pre-quantization bounded-solve residual** and the final quantized on-times (the EKF's control-input bookkeeping uses the quantized on-times — the impulse actually commanded). `sat_flag` derives from the **pre-quantization residual only**: asserted when ‖solve residual‖ > 5% of ‖commanded force‖ (true actuator infeasibility — axis authority lost, demand exceeding jet limits). Quantization error, including its multi-jet aggregate, never feeds the flag; it is ordinary and already accounted for in the quantized-impulse bookkeeping.
- Consumes an availability mask from FSW config — FSW knows which jets *it* has isolated (operator command), never the truth failure state; a stuck-open jet keeps firing in truth until the operator isolates it, exactly the Phase 5 beat-B2 story.

### 5. Sensor models

**File**: `packages/sim-core/src/sensors.ts` (new)

- Samples truth at FSW rate into `SensorFrame`: range (σ scaled with range + floor), bearing pair per the convention defined in §6 (azimuth/elevation of the chaser→target LOS in body axes, seeded noise), gyro reading the kinematic hold rate `[0, 0, n]` + noise, attitude quaternion reporting the propagated `q_BI` + small noise.
- Degrade hooks (bias ramp, dropout → `null`, noise multiplier) built into the model config now — the Phase 5 `NAV_DEGRADE` injection lands on this surface without rework.

### 6. EKF translational navigation (FSW-side)

**File**: `packages/sim-core/src/ekf.ts` (new)

- 6-state (position, velocity) EKF: predict with the discrete CW state-transition plus a control input; update from range + bearing measurements (nonlinear h, standard EKF linearization); tunable Q/R/P₀ in config.
- **Control-input timing (explicit ordering):** within an FSW tick the EKF runs before this tick's controller/allocator, so prediction over the elapsed interval uses the **previous tick's post-allocation, post-quantization nominal impulse** (the on-times FSW actually commanded last tick, converted to specific force via FSW's mass model) — never the current tick's requested force. The FswTick closure retains last-tick on-times for this purpose.
- **Initialization:** position from the first valid range+bearing pair (inverted h), velocity from the guidance reference at that time, with inflated P₀ reflecting both; until a first valid measurement arrives the filter stays uninitialized and telemetry nav fields are the prior.
- **Bearing convention (measurement model):** bearing = (azimuth, elevation) of the unit line-of-sight **from chaser to target**, `l = −r_hill/‖r_hill‖`, expressed in body axes (≡ Hill this phase), boresight +ŷ: **az = atan2(l·x̂, l·ŷ) ∈ (−π, π]** (in-plane angle about ẑ), **el = asin(l·ẑ) ∈ [−π/2, π/2]** (out-of-plane toward +ẑ). Together with range this spans all three LOS components (no degenerate axis) and inverts uniquely. Documented in `sensors.ts` and mirrored exactly in the EKF's h.
- **Pre-initialization telemetry prior:** until the first valid range+bearing pair, telemetry nav fields publish **`FswConfig.initialNavPrior`** (state + covariance) — a field owned by FSW config, deliberately distinct from `SimConfig`'s truth initial conditions. Mission setups will typically choose a prior near the planned approach start (that's what an onboard filter would be loaded with), but the two fields are separate by type so FSW provably never reads truth.
- Publishes full state + full covariance in the FSW diagnostic block (`nav_diag`, see NEES placement); `TelemetryFrame` carries the position estimate and diagonal position variances as today. Handles measurement dropouts (skip update, covariance grows).

### 7. Guidance & controllers (FSW-side)

**File**: `packages/sim-core/src/guidance.ts`, `packages/sim-core/src/control.ts` (new)

- `guidance.ts`: V-bar glideslope approach profile — reference position/velocity vs sim time, closing speed proportional to range down to a 30 m hold point (terminal approach through the corridor is Phase 4's MPC).
- `control.ts`: PID (per-axis, gains in config) and LQR (gain from the discrete CW A/B pair, discrete Riccati solved numerically at FSW init — 6×6, trivial cost) producing commanded force from nav-state error vs the guidance reference. Controller selection via FSW config mirrors `TelemetryFrame.controller`.

### 8. FSW composition

**File**: `packages/sim-core/src/fsw.ts` (new)

- `createFsw(config) → FswTick`: wires EKF → guidance → selected controller → allocator into the single pure entry point per ARCHI (`SensorFrame` in, `{ThrusterCommand, TelemetryFrame, NavDiag}` out). All FSW state (filter covariance, PID integrators) lives in the closure created by the factory; a given seed + input sequence is bit-reproducible.
- Emits `controller`, `control_mode` (AUTO only this phase), `corridor_err_m: null` (Phase 4).

### 9. SimLoop — the public seam

**File**: `packages/sim-core/src/sim.ts` (new)

- `createSimLoop(config, seed)`: owns truth + FSW instances; **`stepTo(t_s): TelemetryFrame[]`** advances truth at `TRUTH_HZ` up to the requested sim time, runs sensors+FSW at `FSW_HZ`, applies commands through the thruster model, computes truth-privileged diagnostics (NEES) into each frame, and **returns every FSW-tick frame produced by the call in order** (one call crossing k FSW ticks returns k frames; a call crossing none returns an empty array). No callbacks, no internal buffering across calls.
- **Command API** (operator surface): `setController('PID'|'LQR')`, `isolateThruster(id)` — what the UI/panel and later the ScenarioDirector call.
- **Injection API** (failure surface): `injectThrusterStuck(id, 'OPEN'|'CLOSED')`, sensor degrade start/stop. Separated from the command API by design (spec §1 lists them as the only two ways in).
- No wall clock anywhere: callers pass target sim time.

### 10. apps/web sim emitter swap

**Files**: `apps/web/src/telemetry/simEmitter.ts` (new), `apps/web/src/telemetry/stubEmitter.ts` (delete), `apps/web/src/App.tsx` (touch imports)

- `simEmitter.ts`: instantiates `createSimLoop` with a fixed seed and the Phase 1 initial conditions ([0, −250, 12] V-bar approach); a `setInterval` at FSW rate advances **sim time by fixed increments** (interval is pacing only — determinism stays sim-time-driven), calling `stepTo` and publishing each returned `TelemetryFrame` to the untouched Phase 1 bus in order. Same `start()/stop()` surface as the stub.
- HUD change (one, explicit): `TelemetryStrip.tsx` PROP cell renders `TelemetryFrame.prop_kg` (kg, 1 decimal) instead of the `----` placeholder. Scene and all other HUD components: unchanged.

## Technical Considerations

- **Pattern Usage**: oracle-test discipline (ARCHI testing gate) — every new math module ships with an analytic/invariant test; CW oracle is the propagator's reference.
- **Package Boundary**: everything except the emitter swap stays in sim-core, no React/Three/DOM; `apps/web` consumes `createSimLoop` from the root export only.
- **FSW purity**: `FswTick` sees only `SensorFrame` + its own closure; NEES computed truth-side in `SimLoop`; no `TruthState` import anywhere under FSW modules (grep-enforced by a test, seeding the Phase 5 honesty-invariant lint).
- **Conventions**: SI units, Hill frame per ARCHI (x̂ radial out, ŷ along-track, ẑ = x̂ × ŷ), body ≡ Hill this phase via prescribed kinematics only (q_BI at LVLH rate, no attitude dynamics or control — Phase 3 owns those).
- **Determinism**: single master seed → derived substreams; fixed-step everything; run fully determined by (config, seed, command/injection sequence with sim-time stamps). No `Date.now`/`performance.now` in sim-core.
- **Performance**: 100 Hz RK4 on a 6-state model + 10 Hz FSW is trivial CPU; keep the web loop advancing sim time in ≤ FSW-tick chunks per interval to avoid frame hitches; no allocations in the truth inner loop.
- **Edge Cases**: propellant exhaustion (thrust → 0, flag in telemetry); all-jets-isolated on an axis (allocator returns best-effort + saturation flag); sensor dropout streaks (EKF covariance growth, HUD `----`); min-impulse limit cycling around the hold point (deadband tuning); stuck-open jet with depleting prop.
