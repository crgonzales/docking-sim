# Phase 3: 6-DOF Attitude, MEKF, Docking Camera & Manual Fly Implementation Plan

## Overview

Replace Phase 2's kinematic LVLH attitude hold with real rigid-body rotational dynamics (inertia tensor, thruster torques from the existing 16-jet geometry, RK4 quaternion integration), estimated by an MEKF fusing gyro + star-tracker measurements and controlled by a quaternion-error attitude loop through a full 6-target (force+torque) allocator. Manual fly goes live — AUTO/MANUAL with selectable RATE (fly-by-wire) and PULSE (direct) sub-modes, driven by mouse+keyboard through the deterministic command API. The web app gains a truth render channel, a switchable camera system (cinematic / chase / cockpit FPV), and a docking-camera PiP with a full alignment display and capture-envelope numbers.

## Problem Statement

Phase 2's attitude is a prescribed kinematic hold: no torques, no attitude estimation, no way to fly. Phase 4 (MPC + abort monitors) and Phase 5 (scenario beats B2 stuck-jet tumble and B4 manual takeover) need real rotational dynamics, an attitude filter, and a working manual-control path. Visually, attitude now matters — and rendering the nav estimate would let filter error move the "real" ship.

## Solution Architecture

**Frames (the load-bearing decision).** `TruthState.q_BI` stays inertial-referenced per ARCHI (q_BI rotates vectors **I→B**). The Hill frame rotates relative to inertial at ω_HI = n·ẑ; **epoch alignment: at t=0 the Hill axes coincide with inertial axes**, so q_IH(t) is the I←H rotation about ẑ by n·t. Following ARCHI's naming (q_XY rotates Y→X): **q_BH(t) = q_BI ⊗ q_IH(t) rotates Hill→body**; the renderer, cameras, and any body→Hill vector rotation use **q_HB = conjugate(q_BH)**. A shared `attitude.ts` module owns the quaternion algebra (Hamilton, scalar-first) plus the q_IH(t)/q_BH/q_HB helpers so truth, FSW, and tests can never disagree on direction conventions — every helper's doc comment states which way it rotates vectors.

**Truth.** Rigid-body Euler equations in body axes (I ω̇ = τ − ω×(Iω)) with a diagonal inertia tensor (~1000 kg class defaults), integrated RK4 at `TRUTH_HZ` alongside translation; q̇_BI from ω with renormalization each step. Thruster forces/torques act in **body** axes; translation acceleration is rotated body→Hill via **q_HB** before entering the CW equations. The Phase 2 `w_body_rps = [0,0,n]` kinematic hold is deleted — the attitude controller now actively maintains LVLH hold as a closed loop.

**FSW.** New `mekf.ts`: 6-state multiplicative EKF (3 attitude error + 3 gyro bias), gyro-propagated reference quaternion, star-tracker quaternion updates, error reset into the reference. Attitude control: quaternion-error PD producing commanded torque (LVLH-hold target in AUTO; rate-command target in MANUAL/RATE). The allocator becomes a true 6-target solve — commanded force *and* commanded torque as equally first-class rows of the existing bounded NNLS system (weights configurable; the Phase 2 torque-nulling objective is the special case τ_cmd = 0).

**Manual fly.** All input flows through the SimLoop command API with sim-time semantics (applied at the next FSW tick), keeping runs bit-reproducible from a scripted command sequence: `setControlMode('AUTO'|'MANUAL')`, `setManualSubMode('RATE'|'PULSE')`, `setManualCommand({translation: Vec3, rotation: Vec3})` with axis values in [−1, 1]. RATE: inputs scale to commanded body rates + translation velocity offsets; FSW closes the loop (attitude/rate hold on release — Crew-Dragon-style). PULSE: inputs map directly to force/torque direction commands fed to the allocator with a fixed per-tick magnitude (Gemini-style, no hold). AUTO ignores manual commands.

**Web.** SimLoop exposes `getRenderState()` — a read-only truth pose snapshot `{t_s, r_hill_m, v_hill_mps, q_BH}` published alongside each telemetry frame on the bus (separate field; instruments keep reading nav — visuals=reality, gauges=FSW belief). Scene renders craft pose from it (existing damp interpolation, now on pose incl. slerp for attitude). `CameraRig` provides three switchable views (key `C`): cinematic (current), third-person chase (follows chaser, attitude-aware offset), cockpit FPV (camera at chaser, looking along the +ŷ docking axis, attitude-coupled, simple viewport frame overlay). Docking PiP: a second small viewport rendered from the chaser's docking port along +ŷ, with a standoff-cross target mesh on the station port, alignment crosshair, and capture-envelope numbers (closing, lateral offset, misalignment, rates) from telemetry with in/out-of-envelope coloring per the Phase 5 spec's envelope (closing 0.03–0.10 m/s, lateral 0.10 m, misalign 4°, rate 0.15°/s).

## Implementation Details

### 1. Quaternion & frame algebra

**File**: `packages/sim-core/src/attitude.ts` (new)

- Hamilton scalar-first helpers: multiply, conjugate, normalize, rotate-vector, small-angle exp/log maps, error quaternion, slerp (slerp exported for the web's interpolation via the public API).
- `hillFromInertial(t_s)` → q_IH(t) from the epoch-aligned n·t rotation; `hillToBody(q_BI, t_s)` → q_BH (rotates vectors H→B) and `bodyToHill(q_BI, t_s)` → q_HB (rotates vectors B→H, = conjugate) — both provided so call sites name the direction they mean. Single source for the frame chain.

### 2. Rigid-body truth dynamics

**File**: `packages/sim-core/src/dynamics.ts` (modify)

- `stepTruth` gains rotational state derivatives: Euler equations with configurable diagonal inertia (defaults sized for the 1000 kg vehicle, e.g. Ixx≈Izz≈600, Iyy≈400 kg·m²) and body-frame torque input; q̇_BI = ½·(−ω)⊗q per the existing I→B convention (matching the Phase 2 closed-form); renormalize per step.
- Translation: thruster specific force arrives in body axes and is rotated to Hill via `bodyToHill` (q_HB) before the CW derivative.
- The kinematic-hold branch (`w_body_rps=[0,0,n]`, fixed-rate q propagation) is removed.
- Oracles: torque-free single-axis spin matches closed form; **conservation of the full inertial angular-momentum vector** — R_IB·(I·ω) compared componentwise against its initial value during an **asymmetric multi-axis torque-free spin** (norm-only checks can miss quaternion sign/order errors that rotate the vector while preserving magnitude); quaternion norm drift bounded (<1e-9 per 10⁴ steps); zero-torque, zero-force runs still match `propagateCW` translationally.

### 3. Thruster torque path

**File**: `packages/sim-core/src/thrusters.ts` (modify)

- `ThrusterApplication.torque_Nm` (already computed) now feeds truth; force/torque are body-frame quantities (doc comment updated — Phase 2's "body ≡ Hill" note deleted).

### 4. Six-target allocator

**File**: `packages/sim-core/src/allocator.ts` (modify)

- `allocate(commandedForce_N, commandedTorque_Nm, availableMask?)`: the stacked system's torque rows get the commanded torque as target (was hard-coded 0); per-axis force/torque weights in config (defaults keep them same order of magnitude via a characteristic-arm scaling). `sat_flag`: pre-quantization residual thresholded per block as **max(absolute floor, 5% of that block's command norm)** — the absolute floors (config: ~0.05 N force, ~0.05 N·m torque) prevent numerical residue from asserting saturation when a block's command is zero (pure-force or pure-torque ticks are the normal case); either block asserting sets the flag.

### 5. Attitude sensors

**File**: `packages/sim-core/src/sensors.ts` (modify)

- Gyro: true ω_body + seeded **random-walk bias** (new per-axis bias state inside the sensor model, rate configurable) + white noise — gives the MEKF's bias states something real to estimate. A **truth-privileged diagnostic getter `getTrueGyroBias()`** on the sensor model (never on `SensorFrame`) exposes the current total bias so the SimLoop/tests can compute the 6-dim attitude NEES; FSW cannot reach it.
- Star tracker (attitude channel): q_BI ⊗ small-angle noise quaternion, existing dropout/degrade hooks apply (Phase 5 `STAR_TRACKER` beats land here).
- **Bearing now attitude-true**: the body-frame bearing measurement is generated from the body-frame LOS, `LOS_B = q_BH-rotate(LOS_H)` — the Phase 2 body≡Hill shortcut is deleted. (Downstream nav handling in §8.)

### 6. MEKF attitude navigation

**File**: `packages/sim-core/src/mekf.ts` (new)

- 6-state multiplicative EKF: δθ (3) + gyro bias (3). Propagation: reference quaternion integrated from bias-corrected gyro; covariance via the standard error-state transition. Update: star-tracker quaternion → small-angle innovation; error reset into reference. Q/R/P₀ config; dropout → propagate-only (covariance grows).
- Diagnostic block (`att_diag`: reference quaternion, bias estimate, 6×6 covariance) surfaced through FswTick for truth-side consistency computation, mirroring the Phase 2 `nav_diag` pattern.
- Consistency gate (test-side): 50-run attitude ANEES on the 6-dim error state (δθ from truth vs reference, bias error) against the χ²₆ₙ/N 95% band with the Phase 2 pass criteria (≥90% epochs + window mean) — truth gyro bias must be observable and converged in the window.

### 7. Attitude control & manual command shaping

**File**: `packages/sim-core/src/control.ts` (modify)

- `createAttitudeController(config)`: quaternion-error PD — torque = −Kp·vec(q_err) − Kd·(ω_est − ω_ref); in AUTO the target is LVLH hold (q_BH → identity, ω_ref = the LVLH base rate expressed in body axes via the current attitude estimate).
- **MANUAL/RATE attitude-reference generator (stateful)**: on **every transition into RATE** (AUTO→MANUAL/RATE and PULSE→RATE alike), capture the current estimated Hill-relative attitude and position as the targets and reset the reference generator + controller integrator state — a stale latched target must never command a snap maneuver; while rotation inputs are held, integrate the commanded relative body rates into the target; on release, the target latches — the PD then holds it (translation analogous: velocity offset while held, position-hold reference latched on release). ω_ref always includes the LVLH base rate in body axes so "holding still" means Hill-frame-fixed, not inertially tumbling.
- Manual shaping: RATE mode maps stick [−1,1] to rate/velocity targets (config: max rates ~1.5°/s, max translation offset ~0.5 m/s); PULSE mode maps active axes to fixed force/torque commands per tick (no reference generator, no hold).

### 8. FSW composition & telemetry

**File**: `packages/sim-core/src/fsw.ts` (modify), `packages/sim-core/src/types.ts` (modify)

- Wiring per tick: MEKF (gyro+star tracker) first → translational EKF → mode branch: AUTO (guidance + PID/LQR + LVLH attitude hold) or MANUAL (RATE: reference-generator loops; PULSE: direct commands) → 6-target allocator. Latest manual command is FSW-config state set through the command surface (`setControlMode`, `setManualSubMode`, `setManualCommand` added to `FswTick`).
- **Frame conversions (explicit, all via the MEKF attitude estimate q̂_BH):** (a) bearing measurements are body-frame — the translational EKF's measurement model maps its Hill-frame state through q̂_BH before comparing (h(x) = bearing of q̂_BH-rotated LOS), and the bearing measurement covariance is inflated by the MEKF's attitude uncertainty as **R_eff = R_sensor + J_θ·P_θθ·J_θᵀ**, where P_θθ is the MEKF's 3×3 attitude-error covariance and J_θ = ∂(az, el)/∂δθ is the Jacobian of the same attitude-aware bearing model with respect to the MEKF's attitude-error state (numeric central differences, matching the existing Jacobian style) — covered by the non-identity-attitude test; (b) AUTO's Hill-frame commanded force is rotated H→B with q̂_BH before entering the (body-frame) allocator; (c) the previous tick's achieved body-frame impulse is rotated B→H with the previous q̂_HB before feeding the translational EKF's control input; (d) RATE-mode translation stick inputs are body-frame (pilot-natural) and rotate B→H for the velocity reference. Tests must exercise a deliberately non-identity attitude through the nav path.
- `TelemetryFrame` additions (additive): `q_BH_est: Quat`, `body_rate_dps_est: Vec3`, `att_sigma_deg: number` (RSS of δθ σ), `manual_sub_mode: 'RATE' | 'PULSE' | null`, `docking: { closing_mps, lateral_m, misalign_deg, rate_dps } | null` (computed FSW-side from nav+MEKF estimates when range < 50 m — instruments show FSW belief; feeds the PiP and later Phase 4/5 monitors). `control_mode` now honestly reflects MANUAL.
- FswTick return gains `att_diag` beside `nav_diag`.

### 9. SimLoop: manual commands, render channel, NEES

**File**: `packages/sim-core/src/sim.ts` (modify)

- Command API additions (deterministic, applied at the next FSW tick): `setControlMode`, `setManualSubMode`, `setManualCommand` — forwarded to FSW's command surface. Injection API unchanged.
- `getRenderState(): {t_s, r_hill_m, v_hill_mps, q_BH}` — truth-privileged read-only snapshot for rendering; also attached to each returned frame envelope via a new `stepTo` return of `{frames, renderState}`? **No** — keep `stepTo(t_s): TelemetryFrame[]` stable; the emitter calls `getRenderState()` once per interval after `stepTo` (render pose at latest sim time is exactly what the scene wants).
- Attitude consistency diagnostics: truth-side attitude NEES from `att_diag` fills a new `TelemetryFrame.att_nees: number | null` beside the translational `nees`. The bias-error component comes from the sensor model's truth-privileged `getTrueGyroBias()` (§5) — SimLoop holds the sensor model, so both δθ (truth q vs reference q) and bias error are available without touching FSW.

### 10. Web: render channel & manual input

**Files**: `apps/web/src/telemetry/bus.ts` (modify), `apps/web/src/telemetry/simEmitter.ts` (modify), `apps/web/src/input/manualControls.ts` (new)

- Bus gains a `renderState` field (published by the emitter each interval alongside frames); scene subscribes to it, HUD keeps reading frames only.
- `manualControls.ts`: mouse+keyboard capture attached while MANUAL — **WASD + R/F** translation (W/S = ±ŷ closing, A/D = ∓ẑ lateral, R/F = ±x̂ radial, body axes), **right-mouse-drag = pitch/yaw**, **Q/E = roll**, `M` toggles AUTO/MANUAL, `T` toggles RATE/PULSE, `C` cycles camera. Emits `setManualCommand` at a fixed cadence (per FSW tick) with normalized axes; no pointer lock needed (drag-based). **Fail-safe zeroing**: a zero command is issued on window blur, `visibilitychange`→hidden, `pointercancel`, mouse-up (listened at window scope so drags released off-canvas still end), MANUAL exit, and component teardown — stuck inputs cannot keep flying the ship.
- Emitter passes commands straight through — determinism holds because commands enter the loop with sim-time application semantics.

### 11. Web: camera rig & docking PiP

**Files**: `apps/web/src/scene/CameraRig.tsx` (new), `apps/web/src/scene/DockingCameraPiP.tsx` (new), `apps/web/src/scene/Spacecraft.tsx` (modify), `apps/web/src/scene/SceneRoot.tsx` (modify), `apps/web/src/hud/Hud.tsx` + `hud.css` (modify)

- `Spacecraft.tsx`: chaser pose from the bus `renderState` (position damp as today + quaternion slerp), orienting the mesh with **q_HB = conjugate(renderState.q_BH)** — mesh-local→Hill is a body→Hill rotation. Station gains a standoff-cross docking target on the −ŷ port.
- `CameraRig.tsx`: owns the active camera per mode — cinematic (current framing), chase (offset behind/above the chaser, attitude-aware), cockpit (at chaser COM + small +ŷ offset, oriented by **q_HB**, CSS viewport-frame overlay in cockpit mode only). Mode in a small zustand UI store; key handling in `manualControls.ts`.
- `DockingCameraPiP.tsx`: bottom-right inset (~28% width) rendered as a second scissored viewport from the docking-port camera along +ŷ; alignment crosshair (CSS/SVG overlay), envelope numbers from `frame.docking` with green/amber in/out coloring per the spec envelope. Render cost: second pass at reduced resolution, only mounted when range < 50 m or in MANUAL — protects the 60 fps budget.
- HUD: ModeBar's AUTO/MANUAL goes live from telemetry, adds RATE/PULSE chip; strip gains ATT σ (deg) and body-rate readout.

## Technical Considerations

- **Pattern Usage**: `att_diag` mirrors the Phase 2 `nav_diag` truth-side-NEES pattern; MEKF gate reuses the ANEES criteria verbatim; allocator extension reuses the bounded NNLS machinery.
- **Package Boundary**: slerp/quaternion needs in the renderer come from sim-core's public `attitude.ts` exports (pure math — no Three.js types cross the boundary; convert to Three quaternions at the call site).
- **Conventions**: q_BI inertial-referenced (unchanged); q_BH derived, epoch-aligned Hill/inertial at t=0 — documented in `attitude.ts` and ARCHI at release. Degrees only at HUD/PiP boundaries.
- **Determinism**: manual commands are sim-time-applied command-API calls — a recorded `(t_s, command)` script reproduces a manual flight bit-exactly (this is also what Phase 5's perfect-operator bot will replay). Wall-clock only paces the emitter, as today.
- **Verification**: single-axis spin closed form, momentum conservation, norm drift bound, MEKF ANEES, allocator 6-target achievement — every new math module has its oracle/invariant.
- **Performance**: PiP is the risk — second render pass gated (range/mode), reduced resolution, no postprocessing in the inset. Attitude math per frame is negligible.
- **Edge Cases**: quaternion double-cover in error computation (shortest-path sign fix); gyro-bias unobservability during star-tracker dropout (covariance must grow — test); allocator torque/force conflict under jet isolation (sat_flag per block); manual input while AUTO (ignored, not queued); PULSE mode with prop exhausted; cockpit camera inside station geometry at contact range (near-plane clamp).
