# Phase 1: Cinematic Visual Base Implementation Plan

## Overview

Replace the placeholder `apps/web` shell with the Phase 1 cinematic scene: a real Earth with atmosphere shader and day/night terminator, HDRI starfield, sun-aligned lighting, glTF spacecraft (station target + capsule chaser), and bloom post-processing. Add the full HUD skeleton (top telemetry strip, caution & warning column, bottom mode bar) in a dark flight-software theme, fed by a stubbed telemetry bus that emits fake `TelemetryFrame` data at FSW rate so all later phases wire real signals into stable interfaces.

## Problem Statement

The web app is a wireframe placeholder. Later phases (dynamics, EKF, MPC, scenario mode) need a stable rendering shell and telemetry interface to develop against; building visuals last would force UI rework in every phase.

## Solution Architecture

Three decoupled layers inside `apps/web` (sim-core is untouched except for its already-public type exports):

1. **Telemetry bus** (`src/telemetry/`) — a zustand store holding the latest `TelemetryFrame` (type imported from `@docking/sim-core` public API) plus a stub emitter that publishes plausible fake frames at `FSW_HZ` (10 Hz). The scene and HUD subscribe to the bus only; nothing subscribes to the emitter. Swapping the stub for the real sim loop in Phase 2 touches one file.
2. **Scene** (`src/scene/`) — react-three-fiber components composed in a `SceneRoot`: `Earth` (custom shader material blending day/night textures across the sun terminator + fresnel atmosphere rim mesh), `Starfield` (HDRI environment background), sun-aligned `directionalLight`, `Spacecraft` (two glTF models via drei `useGLTF`), and an `Effects` composer with bloom.
3. **HUD** (`src/hud/`) — plain React DOM overlay (no Three.js): `TelemetryStrip` (top), `CautionWarningPanel` (left, placeholder entries), `ModeBar` (bottom). Dark flight-software theme, mono type, phosphor-green/amber palette.

Scene frame convention: the render scene is the Hill/LVLH frame in meters, origin at the target COM (ARCHI.md conventions). Earth sits along −x̂ at orbit radius; to avoid float-precision and z-fighting at 6.7e6 m, the Earth/atmosphere pair renders in a scaled group that preserves angular size (distance and radius divided by the same factor), and the canvas enables a logarithmic depth buffer.

## Implementation Details

### 1. Dependencies

**File**: `apps/web/package.json`

**Modifications**:

- Add `@react-three/postprocessing` (+ its `postprocessing` peer) for bloom.
- No other new runtime dependencies; drei (already present) provides `useGLTF`, `Environment`, and loader utilities.

### 2. Assets (real, committed)

**Files**: `apps/web/public/assets/` (new tree: `textures/`, `hdri/`, `models/`), `apps/web/public/assets/ASSETS.md` (new)

- Earth textures from NASA Blue Marble: day color, night lights, and a specular/water mask, each at 2k resolution (keep total texture payload ≤ ~40 MB; 2k is the integrated-GPU budget, not 8k).
- Starfield: one equirectangular star map (NASA SVS / ESO Milky Way panorama class), ≤ 4k. LDR (JPEG) is acceptable in place of HDR: star bloom is excluded by design (intensity clamped below the bloom threshold), so extended dynamic range above 1.0 would be unused.
- Spacecraft glTF from NASA 3D Resources: one station-class target (ISS-derived, decimated if the source model is heavy — target ≤ 150k triangles combined) and one capsule-class chaser (Orion/Dragon-class). Convert to `.glb` if the source is `.obj`/`.usdz`.
- **Normalization during prep (mandatory)**: NASA source models have arbitrary units, pivots, and axes. Each `.glb` is normalized to meter scale, pivot at the vehicle COM, and docking axis aligned to the Hill-frame approach axis (target port faces −ŷ, chaser docking axis +ŷ) so `Spacecraft.tsx` applies positions only, no per-model fudge transforms.
- `ASSETS.md` records, per file: source URL, license (NASA media is public domain — still record attribution), decimation/conversion applied, and the exact normalization transform (scale factor, rotation, pivot offset).

**Risk**: NASA 3D source models vary wildly in size/format; the decimation step is the likely time sink. Fallback if a usable station model can't be sourced: a stylized modular station built from primitives, flagged in `ASSETS.md` as placeholder.

### 3. Telemetry bus

**Files**: `apps/web/src/telemetry/bus.ts` (new), `apps/web/src/telemetry/stubEmitter.ts` (new)

- `bus.ts`: zustand store with the latest `TelemetryFrame`, a monotonic frame counter, and a `publish(frame)` API. Types come from `@docking/sim-core` root export only.
- `stubEmitter.ts`: `start()/stop()` interval at `FSW_HZ` publishing fake frames — range ramping down along a V-bar-ish profile, small seeded pseudo-noise on nav position, static `controller: 'LQR'`, `control_mode: 'AUTO'`, null NEES/corridor (honest placeholders for signals that don't exist yet).
- The emitter is started once in `main.tsx`/`App.tsx`; components never import it.

### 4. Scene components

**Files**: `apps/web/src/scene/SceneRoot.tsx`, `Earth.tsx`, `Starfield.tsx`, `Spacecraft.tsx`, `Effects.tsx`, `sun.ts` (all new)

- `sun.ts`: single module owning the sun direction vector (fixed, chosen for a dramatic terminator view) — consumed by both the directional light and the Earth shader so lighting and terminator can never disagree.
- `Earth.tsx`: sphere with custom `ShaderMaterial` — day/night texture blend by `dot(normal, sunDir)` with a soft terminator band, specular glint on the water mask; separate slightly-larger back-side sphere with additive fresnel rim for the atmosphere. Both live in the scaled group described above.
- `Starfield.tsx`: drei `Environment` with the star HDR as scene background (background only — ambient IBL intensity kept near zero so space stays black). Background intensity is clamped so star luminance stays below the bloom threshold — bloom is reserved for night lights and sun glints; stars do not bloom.
- `Spacecraft.tsx`: `useGLTF` for target (at origin) and chaser; the chaser's position is **bound to the bus** (`nav_r_hill_m` from the latest `TelemetryFrame`), so the stub's ramping range produces visible approach motion and the sim→scene seam is real from day one. The 10 Hz bus frame is the **authoritative target**, not the rendered position: a `useFrame` smoothing step (exponential damp toward the latest bus position) interpolates at render rate so the approach doesn't visibly step at 10 Hz or amplify the seeded nav noise. (Phase 2 may add a dedicated render-state channel for truth vs. nav; for Phase 1 nav position is the render position.) Preload both models. glTF load failures are caught by a scene-local error boundary that renders primitive fallback craft (capsule/box) — Suspense only covers the pending state, not errors.
- `Effects.tsx`: `EffectComposer` with `Bloom`, half-resolution. **HDR contract**: bloom threshold sits at luminance 1.0; the Earth shader outputs night-light and sun-glint contributions with an emissive gain > 1.0 (~2–3×) while day albedo stays < 1.0 — so only lights and glints cross the threshold and the night-side bloom screenshot is guaranteed by construction, not by tuning luck.
- `SceneRoot.tsx`: composes the above inside `<Canvas>` with `dpr={[1, 1.75]}`, `gl={{ logarithmicDepthBuffer: true, powerPreference: 'high-performance' }}`, camera framing chaser and target with Earth limb in shot.

### 5. HUD skeleton

**Files**: `apps/web/src/hud/Hud.tsx`, `TelemetryStrip.tsx`, `CautionWarningPanel.tsx`, `ModeBar.tsx`, `hud.css` (all new)

- `hud.css`: dark flight-software theme — near-black panels, 1px borders, `ui-monospace` stack, phosphor green primary / amber caution palette, uppercase labels. Single source for HUD styling.
- `TelemetryStrip.tsx` (top): RANGE (m), CLOSING (m/s), NAV σ (m), PROP placeholder, T+ mission clock from `t_s`. Display formulas are fixed here so implementers don't guess: `RANGE = ‖nav_r_hill_m‖`; `CLOSING = −Δ(RANGE)/Δt` over consecutive bus frames (positive = approaching); `NAV σ = √(Σ nav_cov_pos_m2)` (RSS of the three per-axis variances, labeled as RSS). Reads the bus via selective zustand selectors.
- `CautionWarningPanel.tsx` (left): fixed grid of C&W tiles (NAV, RCS, GUID, CTRL, PROP, COMM) — all dark/inactive in Phase 1; layout and tile component are the deliverable.
- `ModeBar.tsx` (bottom): controller indicator (PID/LQR/MPC, current one lit from telemetry), AUTO/MANUAL state, sim-time readout.
- `Hud.tsx`: absolute-positioned overlay grid composing the three, `pointer-events: none` (no interactivity in Phase 1).

### 6. App shell rewire

**Files**: `apps/web/src/App.tsx` (rewrite), `apps/web/src/main.tsx` (touch)

- `App.tsx`: drop `TargetPlaceholder` and the inline HUD label; render `SceneRoot` + `Hud`; start/stop the stub emitter on mount/unmount.
- `main.tsx`: unchanged except any provider needed; keep entry minimal.

## Technical Considerations

- **Pattern Usage**: rendering consumes only `@docking/sim-core` root exports (`TelemetryFrame`, `FSW_HZ`); the bus is the single seam between sim and UI (ARCHI.md package boundary).
- **Package Boundary**: no React/Three imports land in sim-core; no sim-core internal paths imported by web. The honesty of this seam is what Phase 2 swaps against.
- **Conventions**: scene graph axes = Hill frame (x̂ radial out, ŷ along-track, ẑ cross-track); chaser placed at negative y. Degrees/display formatting only at the HUD boundary.
- **Determinism**: stub emitter noise uses a small local seeded PRNG so screenshots are reproducible; no wall-clock in the fake `t_s` (frame-count driven).
- **Performance**: 60 fps on integrated GPUs — 2k textures, ≤150k triangles, half-res bloom, dpr clamp, no per-frame allocations in `useFrame`, HUD updates via zustand selectors (React re-renders at 10 Hz max, never per-frame).
- **Float precision**: Earth at true distance breaks depth precision — scaled-group technique + logarithmic depth buffer; documented in `SceneRoot`.
- **Edge Cases**: telemetry bus empty before first frame (HUD renders `----` placeholders, chaser holds initial offset); glTF load failure (scene-local error boundary → primitive fallback craft; Suspense covers loading only); WebGL context loss (default r3f recovery acceptable for Phase 1).
