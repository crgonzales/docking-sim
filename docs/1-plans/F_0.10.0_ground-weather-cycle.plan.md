# Ground presentation and volumetric weather over a full day

## Overview

Give the flight base a grounded appearance and a real-time 24-hour environment. One caller-owned environment clock drives sunlight, cloud advection and regional weather movement. Default speed is 1x as requested; a compact time control permits reviewing morning, noon, sunset and night without waiting a day. User-facing names say volumetric weather, with EVE retained only as inspiration or legacy compatibility identifiers.

## Problem

The current ground view has uniform pavement, no aircraft contact shadow and a static gray ceiling. EveCloudSystem explicitly freezes visual time and never advects media. SUN_DIR is copied once into the atmosphere while base and aircraft use unchanging directional/hemisphere lights. Merely incrementing the weather generation each frame would continually restart the expensive orbital atlas and light caches.

## Solution architecture

- FlightMode owns a deterministic environment clock independent of aircraft dynamics. Both walking and airborne flight use it; game pause/focus loss freezes it. No Date.now-driven simulation. Default starts at 10:00 local solar time at the flight chart origin and progresses at 1x. A clear time selector and speed selector are available while paused. Reset restores start time. Existing DEV cloud-base fixture stays frozen with its original sun/weather unless explicitly opted into a dynamic environment.
- A normalized sun direction rotates once per 86400 game seconds around the world north axis (a fixed-declination/equinox model, not a date-accurate ephemeris). Dawn/evening directions, local longitude adjustment, positive altitude lighting and nighttime cutoff share one mathematical source. Pass an optional stable environment reference into LibraryEffects/Earth; never mutate the module-global SUN_DIR or nonflight modes.
- Moving weather uses a stable canonical weather coordinate frame. A modest eastward wind rotates physical ECEF positions inversely around north before BOTH weather-map and 3D noise sampling. Seeded broad spatial fronts modulate coverage/type only in the opt-in dynamic path; different parts of this field arrive at a site over the day, allowing clear, broken and overcast periods. Preserve exact legacy behavior when disabled, existing altitude support and the reference fixture. This is wind-driven procedural weather, not a meteorological fluid solver or precipitation implementation.
- Prepare the existing orbital opacity atlas once in canonical coordinates with identity advection. Distant lookups inverse-rotate the lookup position by the same current weather transform; direct radial refinement uses the same live media. Continuous wind/time does not trigger an atlas generation change or extra target allocation. Discrete field configuration changes require explicit regeneration, not per-frame restarts.
- Cloud lighting stays in physical ECEF. Refresh frozen light-volume builds on a bounded cadence and validate them against LIVE sun/time/weather, not their own saved inputs. Finish builds and atomically publish them using the existing double buffer. Normal real-time drift may use bounded-age cache data; time seeks invalidate once, and fast previews use bounded fallback while caches catch up. Never reset camera history merely because a compatible light generation publishes. Add weather-motion reprojection at the visible cloud front position only (not the no-cloud scene-depth branch), preserving rebasing and altitude correction.
- Ground details use stable site-local meter coordinates, derivative-filtered pavement/grassy variation and expansion joints, preserving the existing geometry/ground collision plane. Add a single bounded local directional shadow map around the viewer for aircraft/base contact and building shadows; no global terrain casting or per-light maps. Sun and ambient PBR intensities fall at night, runway edge lights become useful after dark. Preserve one composer and one canvas.

## Implementation details and files

1. New `apps/web/src/flight/flightEnvironment.ts`: pure clock, sun and wind/time state; finite input validation, pause/reset/seek, default 1x, public stable render state and change revision. Clock uses accepted active frame delta with bounded catch-up; time speed never speeds aircraft physics. Explicit local solar hours rather than OS timezone claims.
2. New `FlightEnvironmentPanel.tsx` and `flight.css`: compact collapsible environment controls, time display/presets and 1x/test speeds; input focus does not leak walking/aircraft controls. On-change wakes paused rendering and resets its settling budget on explicit seek, not every clock tick.
3. `FlightMode.tsx`, `FlightEvidenceCapture.tsx`: create/advance/reset shared clock once, share ref, update scene lights relative to current floating origin and local sun elevation, include actual environment state in DEV evidence. Preserve fixture route precedence and character input behavior.
4. `LibraryEffects.tsx`, `Earth.tsx`: optional environment/sun state updates before the composer; retain unchanged legacy defaults and resource identities. Keep sky/terrain/ocean/cloud sun coherent. Background/ground/aircraft must darken at night rather than keeping daytime PBR illumination.
5. New `scene/clouds/cloudMotion.ts` plus `cloudWeather.ts`, `shaders/cloudDensity.glsl`: shared CPU/GLSL weather transform and seeded fronts. Defaults are identity/disabled for fixtures; altitude is measured in physical coordinates. Advection rotates both noise domains and both coverage/type lookups exactly once. Canonical CPU oracle available for registration tests.
6. `EveCloudSystem.ts`, `shaders/distantCloud.glsl`: caller frame update, canonical atlas binding snapshot, inverse lookup mapping, live light scheduling/validation and explicit discontinuity handling. No per-frame texture uploads, resource reconstruction, generation storm or atlas rebake. Keep status useful for validation.
7. `vendor/takram/src/shaders/clouds.frag` and `vendor/takram/src/CloudsPass.ts`: conditional motion reprojection seam available only with canonical custom media; other backend and conformance media without the seam continue compiling. Current physical visible front maps to previous physical front using the relative weather rotation; no-cloud velocity remains unchanged. Add an explicit media-motion gate to the pass's existing camera-only stationary shortcut: any changed weather transform disables stationary tuple reuse, without invalidating the whole history. An unchanged transform while paused may use the shortcut. Add a stationary-camera GPU test proving moving cloud-hit coordinates reproject, no-cloud velocity stays camera-only, and unsampled clear/cloud history does not freeze with moving weather.
8. `Airfield.tsx`, new `airfieldSurface.ts`, `HornetModel.tsx`: filtered surface material detail, shadow casting/receiving, nighttime light intensity. Original model assets/transforms and surveyed ground support stay intact. Limit shadow coverage/map size for M3; no new dependencies/assets.
9. Tests adjacent to pure logic; extend existing weather GPU fixture for actual shader parity/motion and public DEV validation access if necessary. Add memo with evidence and remaining limits, update ARCHI.

## Technical considerations

All work is apps/web; sim-core and scenario APIs remain unchanged. World uses +Y north; library ECEF uses +Z north; conversion remains libraryFrame authority. SI units and simulation seconds. Seeded deterministic front functions, no frame-random weather. Freeze time during pause, including temporal settling frames. Legacy SceneRoot and cloud-base comparisons retain original static lighting. Preserve all current memory, iteration and DPR limits. Physical light-volume cache staleness is explicitly bounded; rapidly scrubbed/accelerated weather must not masquerade as valid cached lighting.

## Performance and cost

No new cloud textures, raymarch loops or per-frame atlas work. A few coordinate transforms/front evaluations add shader arithmetic; one local 1024 shadow map adds bounded scene work and about 4 MB depth storage. Exclude terrain from its casters and avoid normal/mask passes rebuilding shadows. Compare same camera/resolution before/after and observe cache regeneration cadence. Keep only the user's existing game tab.

## Backward compatibility

Cloud diagnostics and original static sampler behavior are identity defaults. The cloud-base fixture remains frozen. Flight aircraft controls, parked-aircraft limitation, ground plane, route selection and noon flight physics do not change. EVE identifiers in URLs, shader ABI and internal filenames remain compatibility details, not product branding. Required third-party attribution remains.

## Test impact

- Clock/sun invariants: real-time rate, exactly one 24-hour revolution, midnight continuity, local sunrise/noon/sunset/night direction, deterministic different frame rates, pause/reset/seek and invalid arguments.
- Motion oracle: radial length preserved, inverse mapping and previous-frame mapping compose, fronts remain bounded and locally vary over 24 hours, identity-disabled path unchanged, canonical atlas and volume sample same coordinates. GPU stationary-camera motion check covers both cloud-hit advection and unchanged no-cloud velocity, with the stationary reuse gate disabled only while media moves.
- Light scheduler: stationary real-time refresh without starvation, live age/sun validation, pause no aging, discontinuity invalidation and no atlas generation per tick. Extend the existing GPU weather/conformance fixture for actual transformed media, not only string assertions.
- Affected flight/character/renderer suites and full workspace build. Single-tab screenshots ground at dawn/noon/sunset/night plus airborne and cloud-base regression; inspect logs, motion sequence, night readability and performance.

## Documentation impact

README and scenario spec: none (no setup/public scenario changes). ARCHI and flight-base memo need environment ownership and visual limits. New weather memo uses accurate volumetric-weather naming and credits.
