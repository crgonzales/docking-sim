# Phase 4: MPC Terminal Approach, Passive Abort Safety & Flight-Deck UX Implementation Plan

## Overview

Give the sim constrained terminal guidance and a safety net: a 1 Hz MPC controller solving a constrained QP over a CW prediction horizon (approach-corridor cone, capture-envelope terminal box, thrust limits), real corridor/capture monitors with a passive-abort path, and contact detection that latches DOCKED / COLLISION / ABORT outcomes — the sim becomes a completable docking loop and the exact outcome machinery Phase 5's scenario consumes. Also in scope: the deferred manual-rate tuning pass (v0.4.2 known issue), camera orbit/zoom on the mouse (resolving the right-drag conflict), and a keybinds overlay.

## Problem Statement

PID/LQR track references but know nothing about constraints — nothing stops the vehicle leaving the approach cone or contacting outside the capture envelope, and contact isn't even detected. The MPC selector chip is fake, `corridor_err_m` is a null placeholder, and Phase 5's beats (corridor recapture via MPC, abort outcomes, capture check at contact) have no machinery to land on. Separately: manual rotation is over-damped (~0.15°/s vs 1.5 commanded), the mouse fights between ship and camera, and controls are undiscoverable.

## Solution Architecture

**Corridor & envelope as shared FSW constants.** A single `corridor.ts` module owns the approach-corridor definition (half-angle 10° cone about −ŷ from the target port, engagement region y < 0 within a configurable range) and the capture envelope (closing 0.03–0.10 m/s, lateral ≤ 0.10 m, misalign ≤ 4°, rate ≤ 0.15°/s) with values matching `docs/scenario-mode-spec.md` §4 — MPC constraints, FSW monitors, truth-side contact evaluation, and the HUD PiP coloring all read the same constants, so Phase 5's monitors are literally these.

**MPC (1 Hz, FSW-side).** Decision variables: per-step Hill-frame **specific force (m/s²)** over an N-step horizon (Δt = 1 s, N ≈ 30) — matching `cwDiscreteMatrices`' Γ input units; the commanded output converts to force via FSW's mass estimate (dry + prop estimate), stated explicitly so no N-vs-m/s² mixup survives. Prediction: the exact discrete CW transition already in `ekf.ts` (reused, not re-derived). Cost: quadratic tracking to a capture-approach reference (glideslope toward the port, terminal closing-rate window) + control effort. Constraints: (a) corridor — the 10° second-order cone linearized as an 8-facet polyhedral inner pyramid about −ŷ, applied at a **stage set preselected at solve time from the reference trajectory** (stages whose reference positions lie in the engagement region get facets — decision-independent, so the problem stays a convex QP; conditioning facets on decision-dependent predictions would be nonconvex and is explicitly forbidden); (b) terminal capture constraints on the last horizon states when the reference terminal range is inside capture range (closing-rate bounds, lateral bound); (c) the acceleration authority set below. **Both constraint families are soft** — the corridor gets one slack; the terminal set gets **two separate slacks with unit-normalized penalties** (position slack in metres against the lateral bound, velocity slack in m/s against the closing-rate window — sharing one slack across mixed units would make the penalty meaningless). With every non-authority constraint soft, the point (u = 0, slacks = their violations at free drift) is feasible **by construction**, and the solver is handed that explicit feasible start `x0`. A nonzero optimal corridor slack is NOT a failure — an optimal soft solution *is* the recapture command (this is exactly the corridor-recapture case) and executes; slack magnitudes live in **MPC diagnostics only** — the HUD corridor caution is driven solely by the corridor monitor's `corridor_err_m` (actual geometry, not solver internals), never by slack. **Fallback**: `status ≠ optimal` only → `mpc_fallback` latches and **LQR is recomputed at the full 10 Hz until the next successful MPC solve** — stale held MPC commands are never resumed mid-interval; successful solves are zero-order-held for the 1 s interval as normal.

**MPC acceleration authority (jointly feasible, honestly shaped).** At FSW creation (and on every jet-availability change), the ±axis acceleration magnitudes are found by probing a **side-effect-free scratch allocator instance** (same config, fresh state — the flight allocator's impulse accumulators must never see probe traffic): candidate magnitudes with a required torque-headroom reserve, halved until each probe solves cleanly. Six proven ±axis points define an **inscribed octahedron** — which is what the probing actually proves (not a Cartesian box) — encoded as its 8 linear facets in the QP. MPC never commands what the allocator would back off.

**Monitors & outcomes.** FSW-side corridor monitor computes real `corridor_err_m` (distance outside the cone surface, 0 inside) from nav state. **Two-level corridor response** — a violation must be *recoverable*, or the Phase 5 "switch to MPC and recapture" beat is impossible: (level 1, caution) any excursion outside the 10° cone lights CTRL amber and (in AUTO with MPC) lets MPC drive the recapture; (level 2, abort trigger) only a **sustained** excursion (continuously outside for T_abort = 15 s) or crossing the **hard outer boundary** (15° cone) triggers the automatic passive abort, AUTO mode only. `commandAbort()` on the SimLoop command API (and Backspace in the web app) triggers the same path manually from any mode — the exact surface the Phase 5 guarded ABORT button binds to. Abort sequence (FSW latched state): a guidance-computed **safing burn executed as a bounded-force velocity-target maneuver through the normal controller/allocator path over multiple ticks** (closed loop on the ΔV target using the allocator's achieved-impulse bookkeeping, with a completion tolerance and a timeout), targeting nulled closing rate plus a small opening rate with the CW non-drift condition (ẏ ≈ −2n·x plus opening bias); then thrust cutoff with attitude rate-damping only; latched until reset. **SimLoop is the sole outcome arbitrator**: contact (truth event — port-to-port distance ≤ 0.05 m between the chaser nose port at +1.7 m body ŷ and the station port at −8.7 m Hill ŷ) is evaluated every truth tick against the TRUTH capture envelope → `DOCKED` or `COLLISION`; the FSW abort latch is *reported* to SimLoop, which converts it to the `ABORT` outcome only if no contact outcome exists. Same-tick ordering: contact outcomes are evaluated before the abort mirror. The first latched outcome is immutable — no later event changes it. `DOCKED` pins the **complete relative pose**: position held at the port, velocity zeroed, attitude pinned to port alignment, body rates zeroed, thruster application skipped.

**Tuning pass (manual rates).** Diagnose the over-damped manual rotation (candidates: per-jet impulse-carry smearing alternating-sign torque pulses — likely needs carry zeroing on per-jet command sign flip or a leaky carry; attitude PD kd vs available torque quantum; rate-target shaping). Acceptance: commanded 1.5°/s manual rate achieved within 20% inside 3 s, `manual-coupling` regression stays < 2°, LVLH hold and ANEES gates untouched.

**Web UX.** Mouse becomes camera-only: right-drag orbits (azimuth/elevation around the chaser) in CHASE and CINEMATIC, scroll zooms (clamped), orbit state persists per mode in the view store; COCKPIT keeps the fixed boresight; the manual-rotation drag path is removed (ship rotation = W/S/A/D/Q/E only — the KSP scheme made mouse rotation redundant). Keybinds overlay toggled by `H` (and `?`), rendered from a single exported bindings table that `manualControls.ts` itself consumes for its key handling — one source of truth, so the overlay can never drift from the real bindings; an always-visible `H CONTROLS` hint chip sits bottom-left. Outcome banner (DOCKED / COLLISION / ABORT) as a centered stencil-style HUD element; C&W tiles go live: CTRL amber while `corridor_err_m > 0`, CTRL red + banner on ABORT, GUID amber while `mpc_fallback`.

## Implementation Details

### 1. Dense active-set QP solver

**File**: `packages/sim-core/src/qp.ts` (new)

- `solveQp(H, f, A, b, x0, options)` minimizing ½uᵀHu + fᵀu subject to Au ≤ b; primal active-set method reusing `linalg.ts` solves; iteration cap + convergence tolerance in options; **callers supply an explicit feasible start `x0`** (the MPC formulation constructs one by design: u = 0 with slacks set to their free-drift violations); the solver validates `A·x0 ≤ b` and returns status enum **`'optimal' | 'iteration_capped' | 'numerical_failure'`** (`numerical_failure` covers an invalid x0 or degenerate linear algebra). Phase-I and hard-infeasibility detection are out of scope by design — the formulation makes them unnecessary.
- Oracle tests: KKT stationarity/feasibility/complementarity residuals near zero on solved problems; hand-solvable 2-var QPs with known active sets; unconstrained-case equality with the closed-form −H⁻¹f; iteration-cap and invalid-x0 statuses.

### 2. Corridor & envelope constants

**File**: `packages/sim-core/src/corridor.ts` (new)

- `CORRIDOR` (half-angle 10°, engagement range) and `CAPTURE_ENVELOPE` (0.03–0.10 m/s closing, 0.10 m lateral, 4° misalign, 0.15°/s rate) — values mirrored from spec §4 with a comment pinning that linkage.
- Geometry helpers: `corridorError_m(r_hill)` (distance outside the cone, 0 inside; the cone apex sits at the station port, axis −ŷ), `insideCaptureEnvelope(state…) → per-criterion booleans` (shared by MPC terminal constraints, monitors, truth contact evaluation, and telemetry docking block).

### 3. MPC controller

**File**: `packages/sim-core/src/mpc.ts` (new)

- `createMpc(config)`: horizon N (default 30 × 1 s), builds the condensed QP (state predictions eliminated via the CW transition powers — matrices precomputed at creation since Δt and N are fixed) in **specific-force (m/s²) decision variables**; corridor facets applied at the **reference-preselected stage set** (stages whose reference positions lie in the engagement region — never conditioned on predictions); soft terminal capture constraints when the reference terminal range is inside capture range; the probed octahedral acceleration facets.
- `step(navState, t_s) → {accel_hill_mps2, status, diagnostics}` where `diagnostics.slacks = {corridor_m, terminalPosition_m, terminalVelocity_mps}` (structured — no singular slack field); the FSW caller converts acceleration to force via its mass estimate before allocation. Internally rate-limited to `MPC_HZ`; on non-optimal status the caller runs LQR at 10 Hz until the next successful solve.
- Tests: solved-trajectory constraint satisfaction on feasible scenarios (predicted positions inside corridor facets with zero slacks, terminal states inside the capture set), recapture scenario (start outside the cone → optimal solve with positive corridor slack that decreases over successive solves), **unreachable-terminal scenario** (terminal set not reachable within the horizon → status stays `optimal`, the appropriate terminal slack is positive, no fallback), effort regularization sanity (zero command at the reference), status handling (iteration-cap → fallback), determinism.

### 4. Monitors & abort logic

**File**: `packages/sim-core/src/monitors.ts` (new)

- `corridorMonitor(navState)` → `corridor_err_m` + two-level flags: caution (outside 10° cone, hysteresis-banded so noise doesn't chatter) and abort-trigger (sustained-violation timer ≥ 15 s OR outside the hard 15° outer cone).
- `computeSafingBurn(navState, n)` → ΔV target that nulls closing rate and sets the non-drift + opening condition; execution is the FSW velocity-target maneuver described in the architecture (bounded force, achieved-impulse accounting, tolerance + timeout). Passive-safety oracle (test): propagate the post-burn state with `propagateCW` over 2 full orbits and assert a **minimum keep-out distance** — range never drops below 0.8× the range at the abort epoch (a non-drift CW coast is periodic, so monotonic-range assertions are wrong by construction; keep-out is the physically meaningful property).
- Abort state machine (armed → safing burn in progress → coasting/latched) consumed by fsw.

### 5. FSW wiring

**File**: `packages/sim-core/src/fsw.ts` (modify), `packages/sim-core/src/types.ts` (modify)

- Controller selector accepts `'MPC'`; MPC ticks at 1 Hz inside the 10 Hz FswTick (counter on sensor time), ZOH force between solves; inner attitude loop (LVLH hold / manual) unchanged; PID/LQR paths untouched.
- Corridor monitor runs every tick; caution level lights telemetry in all modes; the abort-trigger level enters abort automatically in AUTO only (MANUAL shows the caution but never auto-aborts — pilot authority); `commandAbort()` on the FswTick command surface enters the same state from any mode.
- Abort state: safing burn commanded through the normal allocator path, then zero translation force + rate-damp attitude; latched; `control_mode` stays honest; telemetry gains `outcome`/`abort` reporting and `mpc_fallback`.
- `TelemetryFrame` additions (additive): `corridor_err_m` becomes real, `outcome: 'NONE' | 'DOCKED' | 'COLLISION' | 'ABORT'`, `mpc_fallback: boolean`.

### 6. SimLoop: contact & outcome latch

**File**: `packages/sim-core/src/sim.ts` (modify)

- Truth-side contact detection each truth tick: port-to-port distance (chaser port at +1.7 m body ŷ via q_HB; station port at [0, −8.7, 0]) ≤ 0.05 m → evaluate `CAPTURE_ENVELOPE` against TRUTH (closing rate along port axis, lateral offset, misalignment from q_BH, body rates) → latch `DOCKED` or `COLLISION`; first outcome wins, director-visible via telemetry.
- `DOCKED`: complete relative pose pinned (position at port, velocity zeroed, attitude pinned to port alignment, body rates zeroed), thruster application skipped — a hard capture, honest enough for Phase 4/5.
- `commandAbort()` forwarded to FSW; SimLoop arbitrates: FSW's abort latch becomes the `ABORT` outcome only when no contact outcome is already latched (contact evaluated first within a tick; first latch immutable).
- Tests: MPC-flown full approach from [0, −250, 12] ends `DOCKED` with all envelope criteria green at contact (the headline closed-loop test and Phase 5's perfect-operator seed); deliberate fast approach ends `COLLISION`; sustained corridor violation in AUTO ends `ABORT` with the post-abort **keep-out oracle** applied to truth (range never below 0.8× the abort-epoch range over 2 orbits of CW propagation); determinism of all three under fixed seeds.

### 7. Manual-rate tuning

**Files**: `packages/sim-core/src/allocator.ts` and/or `control.ts` (modify, guided by diagnosis)

- Instrument first (commanded vs achieved torque through the accumulator under alternating-sign sequences), then tune: candidate levers per the postmortem — per-jet carry zeroing on command sign flip, PD gain rebalance against the torque quantum, rate-target feed-forward. Keep changes minimal and physically argued in comments.
- New closed-loop test: MANUAL/RATE full pitch stick → achieved body rate within 20% of 1.5°/s inside 3 s; `manual-coupling.test.ts` regression must stay < 2°.

### 8. Web: camera orbit & zoom

**Files**: `apps/web/src/scene/CameraRig.tsx` (modify), `apps/web/src/input/manualControls.ts` (modify), `apps/web/src/viewStore.ts` (modify)

- View store gains per-mode orbit state `{azimuth_rad, elevation_rad, distance_m}` with clamps (elevation ±80°, distance 8–400 m chase / 40–2000 m cinematic); right-drag mutates the active mode's orbit; wheel mutates distance (exponential steps); COCKPIT ignores both.
- `CameraRig` composes the orbit offset around the chaser each frame. **Both chase and cinematic orbits are Hill-frame (deliberate amendment during implementation):** an attitude-locked chase orbit spins the camera with every vehicle rotation, which makes manual flying and abort tumbles nauseating to watch — a stable Hill-frame orbit around the craft is the correct UX. The vehicle's attitude remains fully visible because the mesh rotates within the stable frame.
- `manualControls.ts`: drag handlers now write orbit state instead of rotation axes; `dragPitch/dragYaw` and their fail-safe paths are deleted; wheel listener added (preventDefault to stop page scroll); ship rotation is keys-only.

### 9. Web: keybinds overlay, outcome banner, C&W

**Files**: `apps/web/src/input/bindings.ts` (new), `apps/web/src/hud/KeybindsOverlay.tsx` (new), `apps/web/src/hud/OutcomeBanner.tsx` (new), `apps/web/src/hud/CautionWarningPanel.tsx` (modify), `apps/web/src/hud/Hud.tsx` + `hud.css` (modify), `apps/web/src/input/manualControls.ts` (modify)

- `bindings.ts`: the single bindings table `{code, label, group, description}` — consumed by BOTH the key handler (codes) and the overlay (display); adding a binding without overlay coverage becomes impossible.
- Overlay: `H` / `?` toggles a centered dark panel grouped by MODE / TRANSLATE / ROTATE / CAMERA / SAFETY; `H CONTROLS` hint chip bottom-left always visible.
- New keys: `V` cycles PID → LQR → MPC, `Backspace` = abort — both reach the live loop through **new exported pass-throughs in `simEmitter.ts`** (`cycleController()`, `commandAbort()`), following the existing `setControlMode` wrapper pattern.
- `OutcomeBanner`: DOCKED (green) / COLLISION (red) / ABORT (amber) full-width stencil text + sub-line, driven by `frame.outcome`.
- C&W: CTRL tile amber while `corridor_err_m > 0`, red when `outcome === 'ABORT'`; GUID amber while `mpc_fallback`.

## Technical Considerations

- **Pattern Usage**: exact CW discrete transition reused from `ekf.ts`; QP built on `linalg.ts`; monitors/corridor constants shared exactly as the `att_diag`/truth-privileged patterns were; outcome latching mirrors the spec §5 "first outcome latches" semantics.
- **Package Boundary**: all new logic sim-core; web consumes telemetry + command API only.
- **Conventions**: corridor cone about −ŷ from the station port per spec §2; SI in sim-core; degrees only at HUD.
- **Determinism**: MPC is deterministic (fixed matrices, deterministic active-set pivoting); outcome latching driven by sim-time truth events; abort reproducible from the command script.
- **Verification**: QP KKT oracles; passive-safety keep-out oracle via `propagateCW` (range ≥ 0.8× abort-epoch range over 2 orbits); corridor geometry closed-form checks; full-approach DOCKED closed-loop as the headline.
- **Performance**: MPC solves a ~90-var QP once per sim-second — trivial for the browser at real-time rate; precomputed condensed matrices keep per-solve cost to the active-set iterations.
- **Edge Cases**: corridor slack active at engagement entry (an optimal positive-slack solve IS the recapture command — executes with the corridor caution lit, no fallback, no throw); abort triggered while already aborting (idempotent); contact during abort (SimLoop arbitration: contact evaluated first, first latch immutable); MPC selected in MANUAL (manual commands still win — MPC only drives AUTO); docked state with stuck-open jet (thrust ignored once docked); corridor monitor at range ~0 (cone apex singularity — monitor disengages inside capture range); safing-burn timeout with jets isolated (cutoff + latched anyway, coast is best-effort).
