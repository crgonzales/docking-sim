# F/A-18-style flight prototype implementation plan

## Overview
Add a selectable FLIGHT mode to the existing game with an airborne F/A-18C-style aircraft, physical six-degree-of-freedom dynamics, keyboard controls and basic instruments. Default docking, scenario behavior and the parallel cloud renderer remain unchanged. Version 0.13.0 is a planning label only; no release/version bump is authorized.

## Solution architecture
Use a pure TypeScript, data-driven engineering approximation for this bounded milestone, sharing existing scalar-first Hamilton quaternion utilities. Keep a public flight API in sim-core separate from orbital SimLoop and all FSW. A dedicated React scene reuses Earth and WorldFrame, without modifying their internals. A small adapter maps local NED flight coordinates onto the game's spherical Earth near the equatorial ocean origin. Limit operation to a 50 km radius, 0–20 km altitude and subsonic envelope; stop at contact or domain boundary. Aircraft mesh is original procedural geometry; no downloaded assets.

JSBSim is the preferred follow-up backend: official C++/XML 6DOF solver, LGPL. The third-party @0x62/jsbsim-wasm SDK provides an MIT wrapper and LGPL WASM, MEMFS aircraft loading and Vite integration. A real integration still needs a pinned runtime, aircraft/engine/system XML dependency graph, property/unit/frame adapter, fixed-step worker lifecycle, licensing records and native-vs-WASM oracles. No verified reusable F/A-18C coefficient dataset or cleanly licensed visual asset was established in discovery; the FlightGear FA-18 repository advertises undeclared licensing and a temporary noncommercial restriction. Do not copy it or imply validated F/A-18 fidelity.

## Technical considerations
- Flat, nonrotating local NED physics; body FRD. `q_BN` rotates NED→body, scalar-first Hamilton; renormalize after each RK4 step. Spherical presentation is a local map, not a rotating-Earth dynamics claim. Existing Hill/ECI conventions remain authoritative for docking.
- Air velocity is ground velocity minus NED wind, transformed to body. Compute angle of attack and sideslip with finite zero-speed handling. Lift perpendicular to relative velocity, drag opposing it, sideforce transverse; qbar scales coefficients. Bounded post-stall lift/drag continuation is numerical protection, not validated departure behavior.
- Euler rigid-body angular dynamics include diagonal inertia and gyroscopic coupling. Static stability, rate damping, pilot moments and pitch trim act through aerodynamic moments, never by setting angular rates. Gravity acts in NED. Thrust includes spool lag and approximate density lapse.
- Longitudinal trim numerically balances lift/thrust against gravity and drag; trim remains fixed while flying unless pilot commands a change. No hidden attitude/altitude hold.
- Web accumulator calls only complete 0.01 s steps, caps catch-up after stalls and clears it on pause/blur/reset. Render/HUD read snapshots; no sensor/FSW accuracy claim.
- Reuse WorldFrame for precision and Earth as-is. No cloud renderer fixes. Bounded mesh and HUD updates; performance must be measured, not claimed.
