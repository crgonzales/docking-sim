# First docking gameplay — v0.14.0 candidate

## Overview and problem
The sandbox begins by watching automation, while the only mission is a six-minute failure-management exam. Add an approachable, manual first docking with a prepared Dragon, one visible objective and a short retry loop. User has authorized implementation; existing renderer/Dragon work stays intact. No release or push in this task.

## Architecture and behavior
Reuse MISSION, ScenarioDirector, the real 100 Hz simulation, existing RATE attitude/position hold, telemetry bus and docking camera. Add FIRST_DOCKING_01 alongside FINAL_APPROACH_01. MISSION opens a choice of First docking (default) or Emergency approach (existing challenge). Ordinary sandbox and flight remain available.

First docking starts at Hill [0.25, -16.4, 0.15] m (six metre axial port gap); final practice starts [0, -12.4, 0] m (two metre gap). Both use velocity [0,0,0] m/s, attitude error [0,0,0] degrees, body rates [0,0,0] degrees/s, seed 20260911 and MANUAL/RATE/LOW. No failures; a generous 20-minute exercise limit is hidden from the primary beginner HUD. Contact still uses the unchanged physical capture envelope. No input must not dock. A telemetry-driven sequence gives Align, Approach and Capture cues; only the simulation's DOCKED outcome marks completion. Neutral controls keep existing RATE hold. The first exercise configures manual angular damping to [1200,800,1200] N m s/rad: live QA reproduced pulse-induced rotation above the contact limit with the inherited LOW damping. This changes the assist controller only; mass, inertia, pulse sizes, sensor noise and capture limits stay unchanged. Precision input caps target translation to 0.07 m/s; regular approach uses 0.25 m/s with explicit precision selection. An explicit Keep approaching toggle maintains the same forward manual input; it never corrects alignment. Brake/pause/retry clear it, and direct fore/aft input takes over. Inputs are never replaced by an autopilot. Short key taps survive at least one FSW tick; pointer clicks nudge for at least three ticks. Hold position is an explicit public command to capture the next estimated pose and zero pilot commands, then use existing RATE controllers to brake; it never edits truth state.

Expose distance and lateral error at the rotated docking port, not COM range/offset; aim for a 6 cm alignment target inside the physical 10 cm limit, closing speed, lateral/attitude alignment and one actionable hint. A station-anchored target marker and approach rings make the goal visible in chase/cinematic views; a compact head-on alignment display and docking camera support final approach. Keep advanced systems collapsible in this mission. KSP keys remain: Shift/Ctrl fore/aft, IJKL translation, WASD/QE rotation; Space holds position, X toggles precision, P pauses and R retries in first docking. A readable control strip and mouse buttons offer the same precision/hold/pause/retry actions. Do not hijack typing or editable controls.

Full retry resets the same seed and controls; a separately labelled Final 2 m practice restart uses prepared initial conditions (not a fake simulation rewind). Pause/focus loss stops the mission clock and releases held commands. Blur requires explicit resume. Briefing/debrief/pause suppress spacecraft commands. A runtime-owned direct zero-command path bypasses player phase/pause gating and clears commands on every pause/reset/mission transition. Changes of mode/mission/retry clear stale telemetry, input and camera ownership. Launch chooses a useful chase framing instead of inheriting the planet inspection camera.

## Conventions / costs / edge cases
Public sim API only outside sim-core; no truth-driven guidance or teleports after launch. q_BH Hill-to-body scalar-first and SI units. Use estimated pose for readouts, RenderState only for physical presentation. Pure lesson geometry accepts explicit telemetry, has no mutable render dependencies, retains an acquiring-navigation state for null telemetry. Signed axial gap avoids confusing COM range with remaining docking travel. Contact debrief distinguishes too fast, lateral offset, angle and spin using last telemetry (clearly estimated); report uncertainty rather than fabricate a cause when no criterion failed.

No new dependencies, assets, cloud passes or sustained CPU jobs. One 10 Hz runtime and a handful of scene guide primitives. Existing uncommitted renderer/Dragon changes are preserved and excluded from review of gameplay where possible.
