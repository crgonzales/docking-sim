# Changelog - Week 7, 14-09-2026, V. 0.14.1

**Release Date**: Week 7, 14-09-2026 at 15:31
**Version**: 0.14.1 (previously 0.14.0)
**Object**: hotfix: make the library atmosphere pipeline and volumetric weather the only renderer for ordinary play
**Code review**: `docs/3-code-review/CR_w7_v0.14.1.md` (focused independent review)

## Changes

- **Defect**: after v0.14.0 the live site at `https://docking-sim.pages.dev/` and `?mode=mission` still rendered the retired v0.8.0 renderer (old Earth shell and billboard clouds). The released atmosphere and volumetric weather appeared only with `?renderer=library&cloudSystem=volumetric`. FLIGHT was unaffected because it passes both selections explicitly.
- **Fix**: the library atmosphere pipeline is the only renderer. `SceneRoot` mounts `LibraryEffects` unconditionally and no longer mounts the legacy starfield, sun sprite or bloom composer; the `renderer=` query switch is retired. `resolveCloudSystem` defaults to `volumetric` (historical `eve` alias kept; `cloudSystem=legacy` still selects the earlier library cloud backend for comparison). New `scene/renderSelection.ts` resolves every query switch from one search string: medium cloud quality, DPR 1 and exposure 2 by default; `quality=low`, `dpr`, `exposure`, `clouds=0`, `probe=1`, `profile=1`, `weather`, `weatherStructure` and `water` stay explicit overrides; missing, empty and non-numeric values resolve to the defaults (a `dpr=abc` URL no longer yields a NaN canvas DPR).
- **Tests**: `renderSelection.test.ts` covers the bare-URL configuration consumed by SceneRoot and LibraryEffects, mission entry, empty/retired selectors, explicit overrides and FLIGHT-style prop precedence; `cloudSystemSelection.test.ts` now encodes the volumetric default.
- **Not changed**: cloud density, shader lighting, physics, weather-map content and the unrelated `weatherStructure` A/B candidate. FLIGHT's explicit renderer, quality and graphics preferences are untouched. The retired renderer's component files (`Effects.tsx`, `Starfield.tsx`, `SunSprite.tsx`, legacy branches in `Earth.tsx`/terrain shaders) remain in the tree as dead code for a separate cleanup; `DockingCameraPiP` still imports the shared `FRAME_TONE_MAPPING` constant from `Effects.tsx`.
- **Browser validation (production build served locally, one headless Chrome tab, DPR 1, 1280×813 canvas)**: bare `/` and the former explicit URL (`renderer=library&cloudSystem=volumetric&quality=medium&dpr=1&exposure=2`) render the same frame at 60 fps — library atmosphere limb, volumetric clouds, Dragon and station — and both request the four volumetric weather files and the five Takram runtime files; `?mode=mission` shows the first-docking briefing, "Begin docking" starts the mission (Dragon, station, docking camera) and a held Shift raises closing speed from 0.01 to 0.08 m/s with a visible plume; `?flyto=` framings at 400 km (whole-Earth ocean/cloud field with sun glint), 100 km (atmospheric transition with terrain tiles streaming) and 3 km (low-altitude terrain under clouds) render without errors; `?mode=flight` opens on foot beside the parked Hornet at the airfield with Balanced graphics. No console errors or exceptions apart from the pre-existing `/favicon.ico` 404. Not checked: the docking-guide gizmo remains visible from the debug fly camera at orbital distance, and low-altitude source imagery detail keeps its documented softness.
