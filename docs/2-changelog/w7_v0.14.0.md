## Changes

This release publishes everything accumulated since v0.8.0: fourteen integration commits (space-to-ground world, volumetric weather renderer, F/A-18 flight, airfield and real-time daylight) plus the audited first-docking update. Plan numbers 0.9.0–0.13.0 were development labels; 0.14.0 is the first published version after 0.8.0.

- **First docking mission (`F_0.14.0`)**: MISSION now opens a choice of `FIRST_DOCKING_01` (prepared six-metre manual practice on a Crew Dragon, MANUAL/RATE/LOW, seed 20260911, final two-metre restart) and the original emergency scenario. A first-docking HUD reads estimated port geometry, scales existing LOW/RATE input for precision and shows a station-anchored target; explicit forward input never auto-corrects alignment. Public `holdManualPosition()` captures the next estimated pose and resets RATE controllers; braking still uses real thrusters. The web scenario publisher owns pause, short-input latching and seeded restarts; focus loss pauses and clears keyboard and pointer input. No-input and manual-completion oracles, hold dynamics, input ownership and pause/retry tests cover the new seams.
- **Crew Dragon**: CC BY 4.0 "SpaceX - Dragon 2" (KUBAHA) GLB with twelve side and four ring RCS mouths registered from the mesh into `packages/sim-core/src/crewDragon.ts`; revised force/torque allocation and IMU propagation, truth-side docking contact, owned livery/material clones, emissive exhaust pass and a final SMAA pass after atmosphere and tone mapping. Artist-derived geometry with the demo's 25 N jets and tuned mass properties — not a manufacturer-accurate Dragon.
- **Audit fixes**: thruster inspection can no longer start a competing sandbox simulation from MISSION/FLIGHT/ANALYSIS (command and panel are SANDBOX-gated); paused, briefing and debrief states no longer sustain stale RCS audio. Seven regression cases added; the original emitter determinism case restored.
- **Volumetric weather renderer (`F_0.11.0`, `F_0.12.0`)**: library renderer hosted on Takram's Bruneton atmosphere and a maintained Three-clouds fork — canonical world-fixed cloud density feeding local raymarched volumes, a shared light cache averaging transmitted light from canonical subrays, a prepared opacity/height column atlas for orbital views, premultiplied transport over 50–120 km, depth-validated temporal reconstruction, bounded primary spacing with an 800 m stationary depth allowance, and weather advecting about north at 15 m/s with seeded continuous fronts. Implementation, shader macros, assets (`assets/clouds/volumetric/`, `setupVolumetricCloudAssets.mjs`) and diagnostics use volumetric naming; the old `eve` URL value stays readable through one shared parser.
- **Space-to-ground world (`F_0.9.0`)**: bounded best-first quadtree terrain (NOAA ETOPO 2022 base tiles + USGS 1/3-arc-second hero DEMs for KSC and Boca Chica), worker-built height fields, patch-local phase reduction, inside-atmosphere sky and aerial perspective from the baked LUTs, geographic water classifier shared by colour and normal passes.
- **FLIGHT mode (`F_0.13.0`, airfield, `F_0.10.0` ground weather, `F_0.11.0` flight visual quality)**: deterministic 100 Hz rigid-body F/A-18C-style flight with the CC BY 4.0 Rhine_Lab_Muelsyse Hornet through a narrow adapter; an original KSC-inspired airfield (runway, apron, hangars, tower, pad) with an on-foot start beside the parked jet and guarded boarding; `FlightEnvironmentClock` real-time daylight with a single normalized sun driving sky, terrain, ocean and local PBR; cloud-attenuated sunlight and diffuse sky on Hornet/airfield materials; Balanced/High graphics presets (DPR, SMAA, shadow map, anisotropy) with a 2.5 M-pixel allocation cap; aircraft self-shadow bands and cloud-boundary shimmer fixed. Engineering approximation, not a validated F/A-18 model.
- **Workspace and naming cleanup**: single canonical working folder; renderer, assets and docs renamed from the third-party brand to volumetric naming with attribution retained; independent follow-up review approved with no findings.
- **Release packaging**: the web `build` now runs `scripts/setupRendererSpikeAssets.mjs` first, which copies the pinned Takram LUT/noise files from the installed packages, fetches the pinned STBN and licence, and verifies every file against the committed `asset-checksums.json` — a fresh checkout (Cloudflare Pages included) reproduces the ignored runtime assets. `.gitattributes` follows the volumetric asset path. Absolute local paths and agent-tooling references were removed from the published docs.
- **Verification**: `pnpm -r build` passed; 132 sim-core + 38 scenario + 655 web tests passed serially (825). Audit-time gate: 818 tests. Historical GPU/visual evidence lives in `docs/6-memo/volumetric-cloud-system/`, `docs/6-memo/f18-integration/`, `dragon-rcs.md` and `first-docking-gameplay.md`; no fresh visual sweep was run at release time.
