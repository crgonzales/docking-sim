# Changelog - Week 7, 17-09-2026, V. 0.15.1

**Release name**: Under the Hood
**Version**: 0.15.1 (previously 0.15.0)
**Object**: hotfix: reduce orbital cloud blockiness and spacecraft-edge halos
**Code review**: `docs/3-code-review/CR_w7_v0.15.1.md`

## Changes

- Preserve the orbital cloud background when an opaque foreground object lies
  before the cloud layer. Resolve against the destination pixel's full-resolution
  scene depth instead of cutting a coarse cloud-free border around the object.
- Reuse compatible history taps, including genuine clear gaps. Use bounded cubic
  filtering only where the full footprint is compatible; retain guarded bilinear
  filtering at disocclusions.
- Use fresh orbital samples during camera motion and retain temporal accumulation
  while stationary. This avoids making static stochastic lighting sparkle more.
- Apply these changes only to the fully prepared orbital representation. The
  existing 50–120 km transition, near-volume path, cloud density, ray counts and
  quality presets are retained.

## Verification and measured tradeoff

- Production build passes. A source audit checks 285 project modules against
  the released base plus exactly four hotfix files, excluding the unfinished port.
- Type checking and 89 affected tests pass for the byte-identical TypeScript
  portion. The final shader-only correction also passes 15 actual GPU fixtures.
- An independent review approves the exact four-file source delta. Actual built
  shader and entry hashes match the candidate tested on Chromium/Metal, Apple M3.
- Matched mission motion tests reduce image error against a native-ray diagnostic
  reference by about 57% in the cloud background, 63% around Dragon and 59% around
  the station. These are fixture-specific image metrics, not FPS improvements.
- The stationary cloud-background noise measure returns near the release level:
  0.075 versus 0.073 luma levels on an 8-bit scale. An earlier candidate's increased
  stationary sparkle was rejected before release.
- Two release/candidate pairs at 1280 x 800, medium quality, DPR 1 measure the whole
  scene GPU time including picture-in-picture. Stationary medians change from
  9.75–9.86 ms to 10.86–11.12 ms; moving medians from 10.83–11.73 ms to
  13.96–14.28 ms. Moving candidate p95 is 17.50–17.53 ms, slightly above a 60 Hz
  frame budget. This repair has a measured GPU cost and does not promise 60 FPS
  on every device.

## Remaining limits

Newly exposed clouds remain soft while sparse samples and history refill.
Moving reconstruction remains softer than the native-ray diagnostic reference,
and ordinary pixel-edge aliasing remains. This is a bounded repair to the
existing renderer, not acceptance or delivery of the replacement volumetric
weather port. Gameplay, GNC, MATLAB and unreleased development work are unchanged.
