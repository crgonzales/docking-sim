# Single workspace and volumetric renderer naming

The user objected to the proliferation of sibling game folders and the continued use of EVE as the name of this project's cloud renderer. The canonical working folder is now `docking-sim`, on `gameplay-first-docking`. All future game work and the release use this folder.

## Consolidation

- The entire latest integrated update (88 changed/new files at transfer time) was transferred into the canonical checkout without byte changes. Its HEAD remains `77ec02ccbce69f5cb4c85272b9cdfd5dfeed7cfd`.
- The character, cloud, F/A-18, former integrated and render-investigation working copies were moved with Git into `.worktree-archive.local/2026-09-14/worktrees/`. Their branch registrations and earlier work are preserved. The former integrated copy is detached; the canonical folder now owns its branch and changes.
- Before mutation, all seven original worktrees received independent archives of changed files, SHA256 manifests, index/combined patches and status records. Read `.worktree-archive.local/2026-09-14/README.md` and `inventory.json` for recovery. The unrelated nested time-warp worktree was backed up but not changed or moved.
- The original canonical checkout's older staged/unstaged work is preserved in those archives and Git stash. No branches, source history or unreviewed work were deleted. A path-limited stash saved successfully but its cleanup rejected an ignored path; verified backups allowed explicit cleanup before transferring the integrated state. `transfer.json` records the preserved stashes and the original index patch preserves pre-cleanup staging.
- Runtime atmosphere, cloud and STBN assets previously came through absolute symlinks into the old cloud checkout. The canonical project owns physical copies now. Borrowed dependency links were archived and replaced with a clean frozen-lockfile installation (all packages reused locally; no lockfile change). This avoids dependence on sibling paths.

## Naming

- Implementation classes/files are `VolumetricCloudSystem` and `VolumetricAerialPerspectiveEffect`; shader macros, uniform names and diagnostics use `volumetric` / `VOLUMETRIC` prefixes consistently.
- Weather assets are under `apps/web/public/assets/clouds/volumetric/`, generated by `apps/web/scripts/setupVolumetricCloudAssets.mjs`. Binary asset contents are unchanged. Documentation is under `docs/6-memo/volumetric-cloud-system/` and the plan uses `F_0.12.0_volumetric-cloud-system.plan.md`.
- New diagnostic URLs use `cloudSystem=volumetric`. One shared parser retains the old `eve` value for saved URLs; renderer selection and its probe both use that parser. No new evidence or internal status field uses the old brand.
- Actual third-party citations and license notices remain intact. Historical audit records and evidence may retain names/absolute paths from their recorded snapshot. The path mapping is `.evidence.local/workspace-cleanup-2026-09-14/renames.json`.
- Project instructions now require this single working folder and neutral renderer naming; creating sibling working copies requires an explicit user request.
